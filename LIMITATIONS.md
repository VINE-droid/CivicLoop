# Limitations and Honesty Note

*(Starter draft. Update at the end of every phase. Final version ships with the submission.)*

## What is real
- Report capture (text, image upload, category, map pin) with storage in Postgres (Supabase).
- AI understanding: LLM-based category, summary, hazard flags and impact estimate, validated against a schema.
- Duplicate detection using text embeddings, geographic distance and category compatibility.
- Priority scoring: transparent rule-based formula; every factor and point value shown to the user.
- Hotspot detection: distance-based clustering computed from the live data.
- Action brief generated by the LLM from live data (template fallback when unavailable).
- Full status workflow with a status history visible to the citizen.

## What is mocked (and labelled as such in the UI)
- **Login and roles.** A demo role switcher (Citizen / Official). No authentication.
- **Data.** All reports are synthetic, in a fictional ward. No real personal data.
- **Location sensitivity.** Uses a hardcoded landmark list (schools, hospitals, main roads), not a real GIS source.
- **Crews / assignees.** Fictional team names; no real dispatch integration.
- **Notifications.** None are sent. Citizens see status by opening the app.
- **Geocoding.** The map pin is the source of truth. Typed addresses are not verified.

## Where the AI can be wrong
- **Wrong category** when descriptions are vague, mixed, or in unsupported languages. Users can override; officials can edit.
- **False duplicates** when two distinct issues are close together and described similarly (e.g. two potholes on one street). Mitigations: strict thresholds, distance + category checks, and an official's **un-merge** control.
- **Missed duplicates** when wording differs a lot or pins are placed far apart.
- **Hazard and people-affected estimates are guesses** from text/photo. They feed the score, so a wrong estimate can shift priority.
- **Priority weights are our judgment, not validated policy.** They would need tuning with real officials and outcome data.
- **Image understanding is limited** and may be off or skipped. (Update if vision was cut.)
- **Fallback mode** uses keyword rules and is less accurate. It is flagged in the UI when active.

## Safeguards
- Human review: officials can reassign, un-merge and change status. AI never closes or deletes a report.
- Every score is explained from stored factors, so decisions can be audited.
- LLM outputs are validated; failures drop to a labelled fallback rather than silently inventing results.
